# 共通要件

## プロジェクト名

楽ちん報告アプリ（仮）

## 1. アプリの目的

診察時に、お医者さんへ生活状況を説明する手間を減らすための
シンプルな健康ログアプリをFlutterで開発する。

今回開発するのは「プロトタイプ1（MVP）」である。

将来的には蓄積したデータをAI研究などへ活用する構想があるが、
AIによる予測・診断・合併症の予兆検知などは今回実装しない。

## 2. 開発技術

- Framework: Flutter
- Language: Dart
- 対象: スマートフォンアプリ
- 開発段階: Prototype 1 / MVP
- データ保存には Firebase を採用する。
- ユーザー認証には Firebase Authentication を使用する。
- 血糖値、測定日時、食前・食後、メモなどの記録データの保存には Cloud Firestore を使用する。

- Firebase プロジェクトは health_care_app 用として新規作成する。
- 食事写真の撮影・選択・記録への紐付け・表示・変更・削除はMVPの対象とする。写真ファイルの永続的な保存方式・保存先については、アプリの基本機能完成後に検討する。
- 写真の永続保存方式が確定するまでは、アプリ再起動後の写真保持・復元はMVPの完成条件に含めない。
- 写真の保存処理に失敗した場合は、記録全体を保存成功とはせず、記録入力画面に留まってエラーメッセージを表示する。
- 食事写真は保存対象の記録と紐付け、各写真がどの記録に属するか識別できるようにする。
- 既存 SQLite データは Firebase へ自動移行しない。
- Firebase への移行作業時に、既存 SQLite データを無断で削除しない。
- SQLite の削除が必要になった場合は、既存データの有無を確認してから実施する。

認証済みユーザー本人の記録だけを保存・取得できるようにする。

ただし以下を優先すること。

1. 可能な限り無料（0円）
2. プロトタイプとして実装が複雑になりすぎない
3. Flutterとの相性が良い
4. アプリ再起動後もデータを保持できる
5. 将来的にデータ構造を拡張しやすい

有料サービスが必要になる場合は、勝手に導入せずHumanへ確認すること。

## 3. Prototype 1で実装しないもの

以下は今回のMVPから明確に除外する。
- AIによる予測
- AIによる診断
- 合併症の予兆検知
- その他、Prototype 1の完成に不要な高度な機能

これらをCodexの判断で追加実装しないこと。

## 4. Prototype 1の完成条件

以下がすべて動作すればPrototype 1完成とする。

- 同じ画面内で「新規登録」と「ログイン」を切り替えられる
- メールアドレスとパスワードで新規登録でき、登録・認証成功後にカレンダーが表示される
- メールアドレスとパスワードでログインできる
- ログイン成功後、最初にカレンダーが表示される
- 有効な認証状態を保持している場合、起動時にカレンダーが表示される
- カレンダーのボタンから記録入力画面へ遷移できる
- 日付入力で未来日を選択・手入力できない
- 記録がある日付をタップすると、その日の詳細画面が表示される
- 血糖値を入力できる
- 血糖値の入力ルール（整数・0〜600）が機能する
- 現在日時が初期値として自動取得される
- 日時をユーザーが変更できる
- 「食前」「食後」を選択できる
- メモを入力できる
- 食事写真をカメラで撮影できる
- 端末内の既存写真を選択できる
- 写真を最大3枚扱える
- Firebase に記録を保存でき、保存成功後はカレンダー画面へ戻る
- カレンダーから日付を選択できる
- 選択した日の記録を確認できる
- 同じ日の複数記録を確認できる
- アプリを再起動しても保存データが残っている
