# 記録入力画面の要件定義

## 1件の記録として保存する項目

1件の記録は以下の項目を持つ。

### 日時

- 必須
- 現在日時を初期値として自動取得する
- ユーザーによる日時変更を可能にする
- 未来日は入力・保存できない
- 端末のローカル日付を基準に、今日以前の日付を選択可能とする
- 日付ピッカーでは未来日を選択不可とし、未来日を手入力する経路も設けない
- 未来日を選択してからエラーを表示する操作フローは設けない
- 現在日時より未来の日時には、新規記録を追加できない。
- 新規記録・保存済み記録の編集のどちらでも、日時を変更する場合は現在日時より未来の日時を選択できない。
- Prototype 1では日本国内での利用を対象とし、日時は端末の日本時間を基準として扱う。タイムゾーン変更への対応は対象外とする。

### 血糖値

- 必須
- 整数のみ
- 最小値: 0
- 最大値: 600
- 単位: mg/dL 固定
- 小数は許可しない
- 未入力は許可しない

### 測定タイミング

以下の2択。

- 食前
- 食後

必須項目とする。

### メモ

- 任意入力
- 未入力を許可する
- 最大50文字（Prototype 1の仮仕様）

血糖値が高かった・低かった場合などに、
ユーザーが補足情報を入力する目的で使用する。

### 食事写真

- 1件につき0〜3枚
- 最大3枚
- 任意入力
- 写真が0枚でも記録を保存できる
- カメラで新しく撮影できる
- 端末内の既存写真から選択できる

## 保存と画面の状態

- カレンダー画面の記録入力ボタンから開く
- 入力チェックで不備がある場合はエラーを表示し、保存しない
- 保存先は共通要件に従う
- 保存失敗時は入力内容を保持し、エラーを表示する
- 保存に失敗した場合は記録入力画面に留まり、ユーザーが再度保存を実行できるようにする。
- 保存成功後の遷移先は、記録入力画面を開いた経路によって決める。
  - カレンダー画面の「記録入力」から開いた場合は、保存成功後にカレンダー画面へ戻る。
  - 日付ごとの詳細画面の「記録を追加」から開いた場合は、保存成功後に元の日付の詳細画面へ戻り、追加した記録を反映して表示する。
- 保存成功後は入力内容を破棄し、次回記録入力画面を開いた際は新規入力状態として表示する。
- 入力内容が未保存の状態で戻る操作をした場合、
  「入力内容が保存されていません。戻りますか？」と確認を表示する。
  - 「戻る」を選択した場合は入力内容を破棄し、記録入力画面を開いた経路に応じた画面へ戻る。
  - カレンダー画面の「記録入力」から開いた場合は、カレンダー画面へ戻る。
  - 日付ごとの詳細画面の「記録を追加」から開いた場合は、元の日付の詳細画面へ戻る。
- 「キャンセル」を選択した場合は、記録入力画面に留まり、入力内容を保持する。
  - 過去の日時についても、新規記録を追加可能とする。
